# Module 3 — Messaging

## Owner
Chong Zheng Zhe

## Purpose
Supabase-backed ride communication for UC3.4, UC3.7, and UC3.8.

## Implemented Contract

- Phone list/conversation navigation remains split while layouts above 900 px use
  a two-column conversation-list + chat surface. Private and group conversation
  details use the same three-dot `Conversation details and management` action on
  every viewport. The shared adaptive dialog is a scrollable bottom sheet on
  phone and a centred dialog on larger screens, showing live route, lifecycle,
  schedule, roles, and members. The desktop trip-details sidebar is not rendered.
- A signed-in non-Host can open the Host's one persistent direct conversation from a Published ride. The unordered user pair, not the ride, owns the conversation; each ride is retained only as optional context.
- Accepting the first ride request creates the ride's one group chat in the same transaction and adds the Host plus accepted account holder. Later accepted account holders join that group. Companion names never become members.
- A normal user message is one atomic bundle containing any non-empty combination of up to 1,000 text characters, 10 mixed images/videos, and one current GPS location.
- Images: JPEG/PNG/WebP, 10 MB each. Videos: MP4/WebM/QuickTime, 50 MB each. Combined media: 100 MB per message.
- The composer camera action sits beside the file action. It opens a bottom sheet on mobile and an anchored menu on desktop. On mobile, `Take photo` delegates to the operating-system camera through a capture-enabled file input; on desktop, it uses an in-page HTTPS `getUserMedia` preview and captures a JPEG frame. `Record video` stays inside the HTTPS page and uses `getUserMedia` plus `MediaRecorder`; mobile users choose either the front or main (rear) camera before recording, while desktop goes straight to its available front camera. It prefers H.264/AAC MP4 for cross-device playback and falls back to WebM only where necessary, then adds the stopped recording to the existing media draft. The normal file action remains the fallback for unsupported browsers.
- A voice message is a standalone 1-180 second audio attachment limited to 10 MB. Browser `MediaRecorder` manages the recording lifecycle while Web Audio captures a 16 kHz mono PCM WAV playback-safe fallback (about 5.8 MB at three minutes) for Chromium/Electron environments whose WebM output lacks usable media metadata. WebM, MP4, Ogg, and WAV are accepted. Recording is stopped automatically at three minutes; stopped recordings remain as in-memory drafts for preview, retry, or deletion.
- Active direct chats support one-to-one WebRTC voice calls on phone and desktop browsers. The callee can answer or reject a global incoming-call prompt from any authenticated route; connecting, connected, and reconnecting calls can be minimized to a non-modal floating bar with participant, status/duration, mute, expand, and end while the user navigates other app routes. The route-external `CallSessionProvider` keeps the WebRTC session alive. Calls request audio only, release every media track on exit/failure, time out after 45 seconds without an answer, end at 60 minutes, and provide a manual playback action when browser autoplay policy blocks remote audio. Incoming-call state bypasses the PWA data cache and is rechecked after Realtime subscribes/reconnects, browser focus, visibility restoration, and network recovery. Opted-in devices receive a Push-only 45-second incoming-call alert that opens the direct conversation and carries the exact call ID; an already-open call client is focused and resynced without a destructive page reload. Local Vite development unregisters production workers/caches from the same origin so two Chrome profiles cannot remain on different bundles. Cloudflare TURN credentials are issued per participant for 75 minutes by an authenticated Edge Function; an unavailable/stale/900 GB-blocked relay degrades to STUN-only with an in-call warning. Group calls remain outside the current one-to-one scope.
- Received text messages can be translated on demand, and either member's standalone voice message can be transcribed then translated, between English, Simplified Chinese, Bahasa Melayu, and Tamil. The last target language is remembered locally per account. Results are shared and source-versioned in Supabase so repeated requests do not spend the free Cloudflare allowance again.
- Translation uses the authenticated `m3-message-translation` Edge Function. SEA-LION performs language detection and translation; Whisper Large V3 Turbo transcribes private voice audio. Cloudflare credentials remain server-only. Reading a translated result aloud is an independent, user-triggered browser `speechSynthesis` action and is disabled when the device has no matching voice.
- Rendering order for normal bundles is text, ordered media grid, then Google Maps Embed `place` mode. Location is coordinates only; no geocoding. Voice messages render with native audio controls and use `Voice message` in list/history summaries.
- Message and call avatars use the current profile URL when it loads; failed or unavailable external avatar images fall back to the participant's initials instead of leaving a broken image.
- A direct-chat participant's avatar and name link to Module 1's privacy-filtered `/users/:userId` profile. Group headers remain group-level and do not imply a single profile owner.
- The original sender can atomically edit a complete normal bundle only before another member reads it. Voice messages cannot be edited. The sender can delete either message form regardless of read state. Deleted messages remain as tombstones.
- History is oldest-to-newest and searches text, system messages, and media filenames. Results safely highlight the keyword and jump back to the original message.
- Archive is reversible, personal inbox state for both direct and group chats. It never removes membership or makes messaging read-only; any new user message restores the conversation to Messages.
- `Delete chat for me` sets a personal history boundary for direct chats. Earlier messages, media, translations, and calls stay intact for the other participant and never reappear for the deleting user; a later incoming message can surface the conversation again.
- Direct chats expose View profile, Search, Media & files, Archive/Unarchive, Block/Unblock, and Delete chat for me. They never expose Leave/Exit.
- Account blocking stops private messaging/calling, future profile/ride discovery, and new or Pending ride requests in both directions. Existing direct history and accepted-trip safety/group access remain available.
- Completed, Cancelled, and Expired groups remain fully messageable. Travellers may leave individually, producing a system message. The final Traveller departure atomically removes the Host and closes the group; the Host never leaves manually.
- No messaging or call-history access expires because seven days elapsed after a ride ended.
- Active-conversation unread totals appear on the shared Message navigation item. New Realtime notification inserts play one browser-generated bell when the account-local `Alert sounds` preference is enabled; `voice_call` inserts skip that bell because incoming ringing calls use a separate repeating two-pulse ringtone. Sound stops on every call exit state. Autoplay-blocked clients retain visual, vibration, and Push fallback and expose an enable-sound action. A background/closed PWA uses only the operating-system notification sound because Web Push cannot select this custom Web Audio ringtone. Clicking Message or call Push navigates an existing or newly opened PWA window directly to `/message/:conversationId`; `postMessage` is only the compatibility fallback.
- `call_sessions` rows merge with ordinary messages by creation time in the conversation timeline. Entries show local incoming/outgoing direction, terminal result, start time, and connected duration without counting as unread or moving the message read cursor. No call audio is recorded or uploaded.

## Architecture

- Presentation: `src/presentation/components/messaging/` and routes `/message`, `/message/:conversationId`, `/message/:conversationId/history`. `useVideoRecorder.js` owns in-page camera permission, supported MP4/WebM selection, the 50 MB stop guard, and camera-track cleanup.
- Business logic: `src/business-logic/MessagingService.js` validates bundles and voice messages, maps personal archive/delete/block state, resolves legacy direct-chat aliases, and owns the four translation targets. `CallService.js` validates block-aware direct-call eligibility; archive and ride status are not call availability gates.
- Data access: `src/data-access/supabaseMessagingRepository.js` is the production adapter for PostgREST RPC, Realtime, and private Storage signed URLs. `src/data-access/supabaseCallRepository.js` owns call RPCs, call-row Realtime changes, and the private Broadcast signalling channel. `src/data-access/supabaseNotificationRepository.js` is the shared recipient-notification adapter, not a Module 3-specific inbox.
- Translation backend: `supabase/functions/m3-message-translation/index.ts` accepts only a message ID and target language, re-verifies authentication and current conversation visibility, reads private message content server-side, and calls Cloudflare Workers AI. Browser code never receives the Cloudflare token or supplies arbitrary source content/URLs.
- TURN backend: `m3-turn-credentials` re-verifies the authenticated participant and active call before issuing a temporary relay credential; `m3-turn-usage-monitor` reads Cloudflare egress every five minutes, fails closed after 15 minutes without a successful check, and revokes active credentials at 900 GB.
- Database: historical messaging/call migrations remain immutable. Authored `075_m3_conversation_lifecycle_redesign.sql` supersedes their ride-bound direct-chat, terminal read-only, and seven-day retention rules with pair identity, ride contexts, personal state, aliases, blocks, atomic group closure, and updated RLS/RPC contracts.
- The previous `localMessagingStore.js` and dummy message data are legacy-only and are no longer imported by the production Module 3 path.

## Security Boundary

After `075`, call history requires call participation, current membership, and the viewer's `deleted_before` boundary. Group leave/closure removes access; ride age and archive state do not.

Clients receive SELECT-only grants on messaging, translation-cache, and call-session tables. All message/call mutations use narrow authenticated `SECURITY DEFINER` RPCs with empty search paths, `auth.uid()` ownership/membership checks, lifecycle checks, and row locks. Realtime call topics are private and authorize both Broadcast read and write against the active call's two participants. TURN guard/issuance tables have RLS enabled but no browser policy or grant; only server credentials can access them, and long-lived Cloudflare secrets never enter Postgres or Vite. Translation-cache writes use the Edge Runtime's server credential only after a separately authenticated user, active membership, message tombstone, and conversation-expiry check. The `message-media` bucket is private: uploads are owner/conversation staged, listing is blocked, and downloads require a current visible attachment row or the same verified Edge Function boundary.
